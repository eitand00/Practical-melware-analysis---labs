### Question 2
<img width="975" height="72" alt="image" src="https://github.com/user-attachments/assets/76c3eb72-e82f-4fc5-a355-39008404cc10" />

**Answer**

There are couple of ways to check for packed file.  
First thing is we can suspect it at first glance because the file is only 5kb which is quite small.  
The next proof is checking in PEiD.  
* <img width="800" height="600" alt="1" src="https://github.com/user-attachments/assets/f4382212-863f-4d0b-b182-c6508c942df8" />
We see that this is packed in "FSG 1.0 -> dulek/xt" which is a packing method we didn't learn yet but it is a proof that its packed.
The next one is opening PEview and look for clues.
* <img width="800" height="600" alt="1" src="https://github.com/user-attachments/assets/dc332973-c087-48e6-ab6e-83cb892dc6d3" />
We can see that the sections names are missing (where the .data or .text where supposed to be).
* <img width="800" height="600" alt="1" src="https://github.com/user-attachments/assets/3270d7c4-9272-44eb-9012-a374e353cc11" />
Another thing we can see is that the virtual size is way bigger than the raw size.  
The last way is by opening dependency walker and look for imports.
* <img width="800" height="600" alt="1" src="https://github.com/user-attachments/assets/9f45684e-7a2e-4a18-aba7-7ef41e843f67" />
We can see that the imports list is very light and contain is what packed file need.
  *The first is "GetProcAddress" used for loading the full file to the memory.
  *The second is "LoadLibraryA" used to call libraries for the file.
The question asked to unpack in if possible, it is probably possible but not right now (the book taught us only UPX and mentioned that we will learn more packing methods in chapter 18)
